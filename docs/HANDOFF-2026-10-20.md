## 8. 后续发布、备份和结构变更原则

普通发布只上传源码和依赖锁，在 Linux release 内安装生产依赖，复用 `/var/lib/douyu` 和 `/etc/douyu/backend.env`，切换 `/opt/douyu/current` 后重启唯一后端。不要重新导入本地 SQL 和图片，不复制 macOS `node_modules`。

先备份生产数据库、图片、环境配置及旧 release 指向，备份放私有目录并安排离机副本；备份实际是否已建立定时任务和恢复演练尚无完成证据，不能说已有自动灾备。MySQL DDL 可能隐式提交，先核对生产实际结构再审查增量迁移。`schema.sql` 不是现有库升级器，本地 `provision:local` 和迁移脚本不能直接在生产运行。

源码链接回退不恢复 DB/图片；结构变更或写入破坏时先停写、确认恢复点与新增数据，再准备并授权数据恢复。详细安全脚本和 Bash 步骤已在发布手册，不在这里重复一套可能分叉的命令。

Git 提交前只纳入可交付源码、配置样例和文档；必须排除真实 `.env*` 私有配置、`backend/data`、迁移 SQL 数据快照/图片包、SSH/TLS/ACME 文件、数据库管理员配置、日志、`node_modules`、构建缓存和本机工具私有配置。`.gitignore` 另排除 `.idea/`、`exports/` 及导出的个人图纸 `assets/未命名.png`；它们保留在本机。MARD 色卡、许可证、品牌素材和 SQL 结构迁移保留。不能以“用户要求提交”推断允许上传凭据或用户作品。本轮仓库推送结果以最终交付的仓库地址、分支和提交号为准，不把仅生成本文当作已推送。

## 9. 建议阅读顺序与接手步骤

1. 阅读本交接、[IP 体验版手册](./ops/ip-experience.md)、[发布与回滚手册](./ops/aliyun-publishing.md)，再看 `deploy/aliyun/README.md`；10 月 15 日交接作为功能/历史 bug 背景保留。
2. 先区分用户当前要“临时 IP 体验”“本机离线开发”“HTTPS 正式发布”还是具体功能修改。不要把部署待办列表自动变成执行授权。
3. 只读核对仓库当前状态、分支和远端，保留未提交文件；本轮 GitHub 提交号以实际推送结果为准。README 已同步部署记录与本文入口，其他旧文档仍可能保留部署前口径，不能据此重复初始化。
4. 若本次任务涉及启动，先核实本机实际端口/编译进程、导入目录和真实生效 API；不读取秘密，不停止其他项目。环境变量改动后完整重启本项目 watcher，防止缓存旧 `13001`。
5. 若任务涉及远端，先选可用管理员入口并按授权只读核实 service、监听、Nginx 站点、备案和 DNS。当前项目 SSH 只够可选隧道，不能当 root 管理。必要部署检查按该任务授权执行，不自动调用微信登录或 AI。
6. 用户希望别人体验时，优先完成上传/设体验/成员/二维码这些尚未执行的微信步骤；保留手机调试前提，不把 HTTP 体验方式说成正式上线。
7. 正式上线前仍需 HTTPS/合法域名、证书续期、备份恢复、内容审核/举报、监控、防刷及真实设备验收；按具体授权分步完成，不在接手时一口气扩展范围。
