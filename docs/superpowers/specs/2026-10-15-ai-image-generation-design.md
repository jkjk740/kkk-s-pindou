# 豆屿：AI 生图转拼豆图纸设计

日期：2026-10-15

状态：待用户审阅的设计草案；本文件不代表产品代码已经接入、云服务已经配置或实际生图已经验收。

## 1. 已确认的目标与本稿假设

用户确认抠图已可用，要求启动小程序前后端，新增 AI 生成图片后转为像素图的能力；明确选择直接向小程序用户开放，允许低成本付费。

本稿建议使用阿里云百炼北京地域 `z-image-turbo` 正式 API。生成费用由运营者的百炼账号承担；用户充值、支付与套餐不在首版范围。

首版成功标准：登录用户输入中文描述，得到一张可用于拼豆的插画，主动选择后生成可调格数和色数的 MARD 图纸，并沿用现有抠图、修色、保存、跟拼、导出和发布流程。生成模型不负责精确的格阵、豆子数量或 MARD 色号。

## 2. 模型选择与成本

- 推荐百炼 `z-image-turbo`：支持中文描述与快速文生图，适合作为首版的成本与响应速度折中。实际拼豆效果仍需用户验收。
- 每次固定生成一张 `1024*1024` PNG，显式设置 `prompt_extend=false`，不另调用语言模型改写描述。当前北京公开单价为 0.1 元/张；试用额度不作为长期成本依据。
- 魔搭免费推理服务当前定位为非商业、非盈利体验，不用作这次面向用户的正式 API。
- 自部署模型需要额外算力和运维，本轮采用云 API。

- [Z-Image API：参数、同步响应和结果有效期](https://help.aliyun.com/zh/model-studio/z-image-api-reference)
- [百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)

## 3. 页面与交互

保留四个原生 tab。转图页的上传初始态增加次级「AI 生图」入口；已有图纸时也提供紧凑入口。点击进入独立的「AI 生图」页面，返回仍是原编辑草稿。

生成页包括描述输入框、少量可点选的示例描述、今日剩余次数和「生成图片」按钮。首版只提供适合拼豆的插画方向，不增加模型列表、多张批量或复杂参数。统一使用奶油白、豆绿、圆角、自建反馈组件及公共果冻按钮。

用户主动点击生成时才要求登录并创建任务。页面明确说明描述由 AI 处理，结果显示「AI 生成」标识。后台拼接固定的绘图要求：单一主体、居中完整、简单背景、轮廓清楚、大色块、减少渐变和碎小细节，不要求模型绘制网格或色号。用户描述限制为 500 个 Unicode 字符，完整服务端提示词限制在官方 800 字符以内，不静默截断用户输入。

状态依次显示排队、生成、保存结果和图片预览。生成时禁用重复提交，不显示伪造百分比。用户可返回；返回不承诺撤回已经提交给云端的任务，再进入时恢复本人尚未完成的任务或最近一次生成结果。

结果保留「重新生成」和「转为图纸」操作。重新生成是明确的新调用，页面继续显示剩余次数；旧结果保留至新结果成功，失败可继续使用旧图。转为图纸默认 64 格、32 色，用户进入编辑器后沿用现有 24～128 格、最多 221 色配置。

## 4. 保护现有作品

AI 结果作为新的图片来源和新的作品候选，不能继承当前作品 ID、修色、抠图引用或跟拼进度。生成、下载或转换失败时，当前草稿和历史作品保持可继续编辑。

用户点「转为图纸」后，先在独立候选中完成下载、解码、MARD 转换及校验，成功后才切换全局草稿并返回转图 tab。已有未保存草稿时先用自建确认框提示替换当前编辑内容；取消仍保留新生成图片供稍后使用。迟到响应、切页或账号变更不能覆盖其他草稿。

生成原图通过现有私有图片接口读取，保存的作品引用其 `sourceImageId`，因此后续抠图和重开作品可复用现有链路。AI 来源由服务端任务与原图关联判断，个人作品不另改同步协议；公开发布时由服务端将 AI 来源标志写入公开快照，沿公共图纸复制链保留标识，但不公开用户描述、原图、厂商链接或任务内部字段。

## 5. 后端任务与费用控制

新增独立生图服务、厂商适配器、任务仓储和路由，不将付费生图混入抠图服务。继续使用单实例 Node.js 与现有 MySQL。

建议的首版默认值，均可通过后端配置调整：

- 每个登录用户每天最多接纳 3 个新生成任务，每人最多一个未完成任务。
- 全站同时向厂商生成 1 张，最多排队 8 个任务。
- 全站每天最多发起 100 次厂商生成请求；按上海日期计算并在实际派发时通过数据库事务原子预占，跨日队列也占派发当日额度。
- 模型、张数、尺寸和 `prompt_extend` 固定在服务端，客户端不能绕过。

按当前单价，全站派发上限对应约 10 元/日的本功能生图费用，不含其他服务费用；这是应用侧请求上限，不替代云账单。任务失败或结果不确定也保守保留次数占用，防止通过失败重试绕过限额。重复查询、同一请求 ID 重放和已生成图片再次转图不新增生图次数。

客户端在提交前为一次操作持久保存稳定 UUID，并按后端地址和登录账号隔离，后端以 owner + requestId 唯一。同一 UUID 携带不同输入时拒绝，网络重试只找回原任务。鉴权重试也复用相同 UUID。

厂商调用前先持久化派发状态和当日额度占用，不开启 HTTP/SDK 自动重试。同步响应丢失、进程中断等情况下不能保证查回云端生成结果；此类任务显示结果未确认，并提示重新生成可能再次产生费用，不自动发起第二次调用。用户主动重新生成才建立新请求。

收到结果后先记录私有的临时结果引用，再下载、校验并保存图片。若只在结果下载阶段中断，可恢复下载同一结果，不重做生图。厂商链接有效期为 24 小时，链接不返回客户端、不写日志，并在保存完成或失效后移除临时引用。

## 6. 数据与接口

新增生图任务表，主要记录：任务 ID、owner、requestId、请求内容摘要、用户描述、完整提示词版本、模型、尺寸、状态、创建与派发时间、派发日期、厂商请求标识、短期结果引用、私有结果 imageId 和安全错误码。owner + requestId 唯一；owner 及结果图片与现有账号隔离一致。

任务状态为 `queued`（未派发）、`processing`（已预占派发）、`saving`（已收到结果，待私有落盘）、`ready`、`failed`（明确终态）或 `unknown`（厂商调用结果不明）。启动恢复时只有肯定未派发的任务允许开始生成，`saving` 仅恢复下载，`processing` 不自动重发；独立 worker 租约与状态条件更新防止错误领取或重复完成。

另增生图队列锁/按日预算行，串行完成去重、额度预占和派发状态变更。迁移只添加本项目所需表、AI 来源标志列、索引及权限，初始化 schema 和启用生图后的 readiness 校验同步更新，保留既有图片、作品、进度和账号。来源标志字段有兼容旧数据的默认值。

接口沿用现有 Bearer 鉴权及 `{ ok, data }` / 错误 envelope：

| 接口 | 用途 |
| --- | --- |
| `GET /api/generation/capabilities` | 是否配置、本人剩余次数和功能规格 |
| `POST /api/generation/tasks` | `{ requestId, prompt }`，幂等接纳任务 |
| `GET /api/generation/tasks/:id` | 仅查询本人任务与已落盘图片 metadata |
| `GET /api/generation/current` | 找回本人未完成的任务或最近一次生成结果 |

生成图片复用 `bead_images`、100 MiB 用户配额及鉴权下载。图片记录与任务 ready 状态在同一数据库事务提交；只有确认回滚后才删除本次未提交文件，提交结果不确定时保留待核对文件。创建任务前检查空间，保存时再次事务校验；空间不足不得返回假成功。

只下载厂商响应中的受信任 HTTPS OSS 结果地址，限制字节、像素、耗时与重定向；拒绝任意客户端 URL 和内网地址。校验真实单帧 PNG 及预期尺寸后保存，不删除用户已有图片。

## 8. 用户验收重点

- 中文描述生成一张图片并转为 MARD 图纸；64 格/32 色默认正确，调整规格与保存重开正常。
- 未登录、取消登录、未配置、排队、厂商拒绝、断网、额度耗尽和空间不足均可理解并恢复。
- 重复点击、POST 响应丢失、账号隔离、页面返回及重启不会自动重复收费。
- 新图转换失败、取消替换和迟到响应不会破坏现有作品与跟拼进度。
- 生成原图可私有重开与手动抠图，公开图纸保留 AI 标识且不泄露原图或描述。
- 真机保存、分块导出及实际生成质量由用户验收；不把厂商支持和编译成功当作效果保证。
