# 豆屿：本地后端、登录上传与图纸体验设计

日期：2026-10-08。状态：设计及实施计划已获用户批准，代码与专用数据库初始化已实施；未运行测试或验证，等待用户验收。

本稿替代此前「不上传原图、只迁移同步接口」的范围。用户最新确认：自己的原图也上传至本地后端保存，后续再切换 OSS。

## 1. 目标与范围

- 保留 uni-app Vue3 与奶油白、鼠尾草绿风格，不改为原生微信工程。
- 后端从 uniCloud 改为独立 Node.js HTTP 服务，先使用电脑上的 MySQL。
- uniCloud 无业务数据，不做云数据库迁移；本机已有作品必须保留。
- 游客可浏览、体验示例和查看本机图纸；选自己的照片必须先完成真实微信登录。
- 选图成功后上传原图至后端私有存储，再在本机生成图纸；MySQL 保存用户、图片元数据、图纸和拼豆进度。
- 「转图」始终是 tabBar 页；修复导出并增加正面/镜像选择；跟拼支持手势缩放、拖动和图纸详情。
- 当前图纸长边仍是 24 / 32 / 48 / 64 格，最多 24 色，不扩展像素算法和网格上限。
- 本轮不部署 ECS、不购买 OSS、不引入支付、社区、后台管理、Redis 或服务端像素转换。

用户提供的图片仅参考图纸布局与操作需求，不复制作者署名、水印、小红书页面或第三方猫咪图案。

## 2. 实施前检查结果

- 更早的改动前基线为现有 66 个测试及 uni-app 源码检查通过，不代表新需求已实现。用户最新要求：此后开发过程中不由代理运行测试、构建或验证，验收由用户负责。
- `src/pages.json` 已将 editor 注册为 tabBar 页，首页也使用 `switchTab`；editor 的 `onShow` 主动隐藏 tabBar，并显示返回按钮。
- 跟拼只有 1× / 2.5× 两档放大及滚动，没有双指缩放或图纸详情；画布点击用于选行。
- 导出事件已有绑定，但没有共享的导出忙碌状态、镜像选择与阶段反馈。当前样式没有四边坐标、红色分区线，输出尺寸依赖平台默认值。
- 导出无响应的具体真机原因未复现；不能将隐藏画布的 CSS 尺寸直接当作原因。需要验证画布节点、PNG 编码、权限和相册保存各阶段。
- 系统侧滑退出的确切触发方式未复现。恢复 tabBar 不等于能保证拦截微信根页面系统返回手势。

## 3. 后端架构选择

推荐 Express + mysql2 的单体 Node.js 服务：便于复用既有 JavaScript 校验和同步逻辑，也便于之后部署 Ubuntu ECS。

备选 Fastify 可提供 schema 化路由，但会增加既有协议适配；NestJS 适合较大后台，本轮登录、上传与作品同步不需要其框架层级。采用推荐方案，不双维护多个后端。

新增 `backend/`，包含服务入口、配置、业务校验、微信适配、MySQL 仓储、文件存储适配、SQL 和运行说明。不覆盖浏览器设计原型的 `server.mjs`。

从旧云函数复用既有鉴权、校验、版本冲突和删除语义，将所需纯业务代码放入独立后端。新后端不能依赖 uniCloud SDK、云函数入口、云数据库仓储或旧目录的运行环境。旧云函数源码暂不删除，但标记为历史方案，不作为默认运行入口；现有测试文件保留，本轮不运行。

前端用 `uni.request` / `uni.uploadFile` / `uni.downloadFile` 接入，保留业务客户端可注入接口。新后端配置与旧 uniCloud 登录缓存隔离，按服务地址划分登录作用域，令牌不发送给其他服务地址。

## 4. 登录与选图流程

1. 点击「用自己的照片」或转图页「更换照片」时检查本地登录态。
2. 未登录显示明确的登录弹层，说明原图将保存至自己的账号；提供「微信登录」「暂不登录」。取消后仍留在原 tab，不弹出选图、不上传、不生成个人图纸。
3. 用户点击登录后，`uni.login` 获取微信 code，后端通过真实 `code2Session` 验证身份，写入/更新用户记录，再签发既有 HMAC 会话令牌。不要求手机号、头像或昵称。
4. 登录成功后打开相册或相机。只接受 JPEG / PNG / WebP，选择原始文件；不支持的格式提示换图，不悄悄把压缩图宣称为原图备份。
5. 后端校验和保存原图，返回不含服务器路径的图片 ID 与尺寸信息，然后前端使用本机选中的图片进行像素转换。
6. 上传或登录失败保留旧草稿，并明确「尚未上传」；不能绕过登录、制造假用户或显示保存成功。
7. 转图完成后关联 `sourceImageId`；保存图纸仍先可靠落本机，再由用户同步到 MySQL。上传原图成功不等于图纸也已同步。
8. 已缓存且仍有效的登录令牌可用于登录状态展示；服务端对每次原图上传、读取和作品操作重新校验令牌。过期自动更新一次，仍失败则提示重新登录。

本地旧作品保持可查看、导出与跟拼，不要求为离线旧内容强制登录。跨微信账号不得混合个人图片/作品；检测账号变化时保留数据并提示，沿用现有保护流程，不静默改归属。

## 5. HTTP 接口

保留 `POST /api/sync` 的 action 协议，响应为 `{ ok, data }` 或 `{ ok: false, error }`。

| 接口 | 权限与行为 |
| --- | --- |
| `POST /api/sync`，`auth.login` | 仅接受微信 code；真实换取身份、更新用户并签发会话 |
| `POST /api/sync`，`works.list` | 已登录；按当前用户、稳定 ID 分页，包含删除标记 |
| `POST /api/sync`，`works.save` | 已登录；校验图纸、进度、基础版本和可选 `sourceImageId` 的归属 |
| `POST /api/sync`，`works.delete` | 已登录；持久化删除标记，幂等重试 |
| `POST /api/images` | 已登录；multipart 字段 `file`，只上传一张图片，返回图片元数据 |
| `GET /api/images/:id` | 已登录；只返回自己图片的元数据，不返回磁盘路径或永久公开链接 |
| `GET /api/images/:id/content` | 已登录；读取自己原图，私有响应，不直接开放上传目录 |
| `GET /health/live` | 进程存活；不返回敏感配置 |
| `GET /health/ready` | 检查数据库、必需配置及存储目录是否就绪，不制造内存仓储降级成功 |

令牌仅使用 `Authorization: Bearer <token>`；不放在 URL 或严格业务请求体内。作品保存中 `sourceImageId` 缺省/空值用于示例和历史作品，保存个人来源必须指向当前用户已上传且可读的图片。

图片私有地址不直接交给 `previewImage`；先携带鉴权头下载为本机临时文件，再预览。服务端不接受客户端传入 owner、文件路径或对象存储路径。

保留 64 KiB JSON 请求体、64×64 图纸边界、221 色号白名单、进度边界及每页最多 20 项。multipart 单独限流和限大小；上传接口不能复用 JSON 限制或开启全局无界缓冲。

所有失败使用对应 HTTP 状态码和安全文案，不返回 SQL、绝对磁盘路径、堆栈、微信 code、openid、session_key 或密钥。登录/上传设限速，防止请求消耗失控。

## 6. MySQL 表结构设计

仅在 `127.0.0.1:3306` 新建专用数据库 `bead_island`，使用 `utf8mb4`。建库/建表使用本机管理凭据，应用账号 `bead_island_app` 仅具有本库所需 CRUD 权限，不使用 root 常驻运行。不得连接、改密码、建表、清空或修改 blessapp 的 `3307/myapp`，也不得在 3306 的其他现有库中放入本项目表。

身份沿用 `u_` + SHA-256(AppID, openid)，66 个 ASCII 字符；不必保存原始 openid，更不保存微信 session_key 或明文会话令牌。

### 6.1 `bead_users`

| 字段 | 类型与用途 |
| --- | --- |
| `id` | `CHAR(66)`，大小写敏感的 ASCII 主键，微信派生身份 |
| `app_id` | `VARCHAR(32)`，微信 AppID |
| `created_at`、`updated_at`、`last_login_at` | `BIGINT`，毫秒时间戳 |

不新增头像、手机号等非必要信息。首次并发登录通过主键约束确保只有一条用户记录；数据库失败不能签发一个假装完成注册的登录结果。

### 6.2 `bead_images`

| 字段 | 类型与用途 |
| --- | --- |
| `id` | `CHAR(36)`，服务端随机 UUID 主键 |
| `owner` | `CHAR(66)`，用户 ID；建立 `(owner, id)` 唯一约束与用户外键 |
| `storage_provider` | `VARCHAR(16)`，当前 `local`，后续可为 `oss` |
| `storage_key` | `VARCHAR(255)`，服务端生成的对象标识，不是公开 URL |
| `mime_type` | `VARCHAR(32)`，由实际图片内容验证得到 |
| `byte_size`、`width`、`height` | 图片大小与实际解码尺寸 |
| `sha256` | `CHAR(64)`，内容校验值，不对外作为公开检索入口 |
| `created_at` | `BIGINT`，毫秒时间戳 |

图片二进制不放 MySQL，不保存未经处理的用户文件名；元数据与私有文件必须一致，不能只保存临时选图路径。

### 6.3 `bead_works`

| 字段 | 类型与用途 |
| --- | --- |
| `id` | `CHAR(64)`，SHA-256(owner, clientId) 派生主键 |
| `owner` | `CHAR(66)`，用户外键 |
| `client_id` | `VARCHAR(128)`，大小写敏感的稳定本机作品 ID |
| `source_image_id` | 可空 `CHAR(36)`；以 `(owner, source_image_id)` 关联自己原图 |
| `pattern` | `JSON`；图纸版本、名称、尺寸、豆子大小和色号数组，删除标记可空 |
| `completed_rows` | `JSON`，去重且受图纸行数约束的完成行号 |
| `created_at`、`updated_at` | `BIGINT`，毫秒时间戳 |
| `revision` | `BIGINT`，递增乐观锁版本，限定 JS 安全整数范围 |
| `deleted` | 删除标记 |

唯一索引 `(owner, client_id)` 支持用户隔离与稳定游标。不能以更新时间分页，不能先查询后无条件更新；创建必须原子插入，更新必须同时匹配 owner、作品 ID 和基础 revision。

删除作品不自动删除原图，因为多个作品可能关联同一张原图，本轮也没有要求永久删除图片。文件清理不得未经用户确认永久删除个人图片。

用参数化 SQL、受控连接池和连接超时；JSON 与 BIGINT 显式规范化。应用启动不自动清空、修改其他数据库，不用内存仓储冒充数据库。

## 7. 原图存储与后续 OSS

当前存入被忽略的 `backend/data/uploads/`，仅后端访问。服务端生成路径和对象标识，禁止路径穿越；不挂载为公开静态目录、不接受 SVG/HTML/可执行文件、不信任 MIME 头和后缀。

默认单张上限 10 MiB、解码上限 2000 万像素，每用户最多 100 MiB 原图。验真实图片格式和解码尺寸；先鉴权再读取文件，请求超过限制及时终止。配额校验及新增元数据需按用户串行化/事务保护，不能并发突破配额。

上传只接受来自用户本次选择的文件，后端不抓取客户端任意远程 URL。落盘和数据库失败均返回失败并处理临时文件；已持久化的个人原图不能作为临时文件清理。

存储层只暴露保存、读取、清理本次失败临时对象等受控操作。之后用同一对象标识协议接私有 OSS，API/图纸格式不必变；这轮不安装 OSS 凭据、不设置 Bucket，也不把 AK/SK 放进小程序。

原图确实传至后端，微信隐私保护指引必须反映真实处理目的、存储方式和保存相册能力。登录本身不能替代微信隐私或相册授权。

## 8. 转图 tabBar 与导航

- editor 保持原 `pages.json` 注册与 `switchTab` 入口，不新增一个非 tabBar 编辑页。
- 删除 editor 主动隐藏 tabBar 的逻辑，显示真正的微信 tabBar，不制作视觉假 tabBar。
- 移除转图页误导性的返回箭头；转图工具栏为导出、材料、保存，不以系统返回箭头模拟切 tab。
- 固定工具栏、弹层及画布为 tabBar 和底部安全区留空间；不得遮挡「发现 / 转图 / 色号 / 作品」。
- 切 tab 保留草稿并取消过时转换/上传回调，不让旧请求覆盖新作品。
- 跟拼仍可从保存完成进入独立页面；返回或「修色」回 editor 后 tabBar 可见。
- 根页面的系统侧滑行为由用户在真机验收；不承诺以网页拦截代码阻止微信原生退出。用户应通过可见的 tabBar 切换主栏目。

## 9. 高清正面 / 镜像导出

### 9.1 操作与反馈

点击「导出」打开同页底部面板，默认选「正面」，可改「镜像」；展示方向、预计像素尺寸和「保存高清图纸到相册」。镜像说明为「左右翻转图案，色号文字保持正向」。

主导出按钮和材料清单导出共用流程、忙碌状态和重复点击保护。提供准备画布、生成 PNG、保存相册的可见反馈，任何阶段失败都结束 loading 并显示对应提示。

绘制完成、拿到有效临时 PNG 后再保存相册，只在保存回调成功后显示成功。用户拒绝相册权限时说明原因，提供主动打开设置并重试保存的入口；不自动跳设置、不伪造保存成功。

### 9.2 图纸布局

- 白色页面，顶部作品名以及「宽×高 / 实际色数 / 总豆数 / 正面或镜像」。
- 每个非透明格填豆子颜色并标注直立色号，深色格白字、浅色格深字；透明格白底，不计为豆子。
- 上、下、左、右四边逐格坐标；细灰线为基本格线，每 5 格红色分区线，每 10 格更粗红线，边界加框。
- 下方材料图例：色块、色号、数量；可选简短实物尺寸说明和「豆屿」标识，不复制参考图中的作者信息。
- 长标题与最多 24 色材料图例必须换行/裁切在测量边界内，不能覆盖图纸或被图片底边切掉。
- 镜像只改变每行色块的绘制索引，不能整体翻转 Canvas 导致坐标、标题、色号反字；源图纸、进度、用量不变。

### 9.3 高清定义

从色号网格重新绘制 PNG，不截取页面或缩放预览截图。每格 40 个输出像素，当前 64×64 上限约为 2800×3200 像素，实际尺寸由标题、坐标和材料清单布局计算；画布源尺寸、目标尺寸明确，不再隐式乘设备 DPR。

导出像素总量设置上限并提前校验，不为了更高 DPR 盲目扩大内存；目标单张 PNG 不超过 1200 万像素。低内存或原生编码失败要提示，不静默输出模糊图。当前不扩展至 160×160 或多页导出。

组件内 Canvas 导出必须正确传递作用域/节点；初始化和绘制生命周期由用户在原生微信端验收。参数以 [DCloud Canvas 导出文档](https://uniapp.dcloud.net.cn/api/canvas/canvasToTempFilePath) 为准。

## 10. 跟拼缩放、拖动与图纸详情

采用可复用图纸查看器：展示现有 Canvas 或生成的清晰图纸，支持双指缩放、单指平移、`−` / `＋`、当前百分比、「适应屏幕」「查看详情」。查看器不增加算法或改动原始 cells。

| Before | After | Why |
| --- | --- | --- |
| 只有 1× / 2.5× 两档 | 相对适应屏幕 1×–6× 连续缩放、按钮和复位 | 小色号可读，操作不依赖一种手势 |
| 触摸仅用于选行 | 查看模式与选行模式有明确状态 | 避免点击详情与选行抢同一个事件 |
| 无详情入口 | 默认查看模式下点图纸 / 点「查看详情」打开同页全屏查看器 | 不新增页面栈，返回体验可控 |
| 拖动可能与点选混淆 | 多指或超过拖动阈值不触发点选 | 保护当前行与跟拼进度 |

默认查看模式：单击图纸打开详情；行号按钮一直可选行。用户打开「点图选行」后，画布点击选择准确行号，不再打开详情；显式「查看详情」仍可用。

同页全屏详情共享缩放、色号、高亮和进度，关闭不重置作品；不能把查看图片误判为完成一行。详情提供完整图纸、尺寸、色数、豆数与材料信息；个人原图已关联且已登录时可读取并预览原图，示例没有原图也可查看图纸详情。

考虑 uni-app 的 `movable-area` / `movable-view` 或统一手势状态控制；数值缩放和位置必须有单一来源。拖动/捏合时取消点选，缩放以触点为锚，不从左上角跳动；缩放与位移进行逆变换后再计算格子坐标。页面其他区域仍正常滚动，边界受控。

原生组件约束以 [DCloud movable-view 文档](https://uniapp.dcloud.net.cn/component/movable-view) 为准；图片详情若使用原生预览，以 [DCloud 图片 API](https://uniapp.dcloud.net.cn/api/media/image) 为准。不能用浏览器预览替代真机手势验收。

沿用 Emil 的即时反馈与克制动效：点按反馈短而明确，拖动/缩放直接跟手，不每次重新计算色卡或播放装饰动画，触控目标至少约 44px，安全区和减少动画偏好受尊重。

## 11. 本地配置与安全边界

实施后提供 `backend/.env.example`；真实配置由用户填写在忽略且限制访问的 `backend/.env`，不发送到聊天、不回显、不读取其他项目密钥。
