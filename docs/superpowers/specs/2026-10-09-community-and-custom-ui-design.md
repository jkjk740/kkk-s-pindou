# 豆屿：图纸广场与统一交互设计

日期：2026-10-09

状态：视觉方案和本文件已获用户确认。当前进入实现计划编写；实现计划确认前不修改产品代码、不执行数据库迁移。

## 1. 已确认的需求与本轮修订

- 首页直接展示「图纸广场」，删除「灵感」入口、原首页营销文案和重复说明。保留现有四个 tab：发现、转图、色号、作品。
- 图纸广场为双列瀑布流，支持按作品名称或作者名称搜索，以及「最热 / 最新」排序。最热按下载次数降序排列。
- 用户登录后可发布自己的图纸；发布页只有选作品和作品名称，不填写昵称。作者名称由后端读取当前登录账号资料，不能由发布请求指定。
- 图纸详情、材料清单及导出图片使用现有 MARD 豆子色号，如 M12、G3、F17、B25；不展示 HEX，不将所有真实色号改造成 M 开头。HEX/RGB 仅用于内部绘制。
- 下载可选正面或镜像，高清 PNG 保存到手机相册；后端记录下载次数，列表和详情展示。
- 瀑布流新卡片错峰从下往上入场，略微越过终点后回弹；旧卡片和顶部导航不重复播放动效。
- 所有页面固定顶部状态栏安全区和自定义导航，只滚动内容区域。
- 沿用已批准的奶油白、鼠尾草绿和深森林绿视觉，简化页面文字。
- 所有业务登录、确认、提示、操作、导出及加载弹层统一自定义组件，不使用 `uni.showModal`、`uni.showToast` 等原生业务弹层。
- 我的作品删除汇总大卡片、保存位置提示、同步说明、同步按钮和逐卡同步状态。保存后直接出现在作品列表。
- 只使用本项目 Node.js 后端与 `127.0.0.1:3306/bead_island`；不访问或修改 bless 的 3307、其他数据库或原 uniCloud 服务空间。
- 用户负责测试和验证；代理不运行测试、lint、构建、接口联调、健康检查或模拟器验收。

视觉参考：已展示的图纸广场设计图。用户本轮明确修订优先于图中的「灵感」分段、HEX 图例和发布昵称输入框，不再照搬这些元素。

- `bead_users` 和登录响应当前只有身份信息，没有昵称。不能把用户 ID 当成作者昵称，也不能声称已经自动取得真实微信名称。

## 3. 页面与操作流程

### 3.1 图纸广场首页

固定区域为状态栏、豆屿导航、搜索框及「最热 / 最新」筛选。导航提供紧凑的发布入口；未登录点击时打开自定义登录面板。

下方内容采用两个独立高度的列，缩略图按图纸宽高比例展示，卡片高低错落，不用补空白对齐成普通网格。卡片只展示缩略图、作品名、作者名称和下载数量，不添加点赞、评论、关注或重复宣传文案。

游客可以浏览和搜索。输入停顿约 250ms 后请求；切换搜索或排序时取消旧结果的影响并重新加载。首次最多 20 项，触底续页；按公开作品 ID 去重，追加数据不重排已显示卡片。下载量变化后的最新排序在刷新时体现，不让正在查看的卡片突然换位置。

加载使用同尺寸的浅色占位块；失败显示短文案和重试入口，空结果显示「没有找到图纸」。不使用循环跳动的装饰动画。

### 3.2 公开图纸详情

新增独立社区详情页，固定导航和底部按钮。详情展示大图、作品名称、账号作者名称、格数、色数、豆数、下载次数，以及真实 MARD 色号与数量。

点击大图打开现有自定义图纸查看器，支持放大、缩小、平移和恢复适应屏幕；沿用最近的手势状态隔离，不重新引入缩放反馈循环。公开详情不提供私人原图入口，也不展示作者的跟拼进度、私有作品 ID 或个人图片链接。

底部「开始拼」将公开图纸复制为自己的独立作品，进度从零开始，再进入跟拼。「下载图纸」打开自定义正面 / 镜像导出面板。开始拼本身不计下载次数。

复制后的图纸允许修色、导出和跟拼，但不因为复制自动将别人的作品重新发布；本轮不实现二次发布他人图纸。私人作品保存与公开发布是两个独立行为。

### 3.3 发布作品

登录后从我的作品选择自己的图纸，预览并填写作品名称，点击「发布作品」。名称默认沿用原作品名；不出现作者昵称输入框。

前端先确保所选作品以最新版本保存到个人后端，再提交其作品 ID 和版本。后端检查所有权与版本，复制一份公开图纸快照，并生成缩略图。不接受客户端提交作者、owner、下载量、原图地址或存储路径。

唯一的隐私提示为「只分享图纸，不公开原图」。公开内容不包含 `sourceImageId`、原图二进制、EXIF、完成行号或私有同步字段。

发布有重复点击保护。同一用户的同一个源作品只对应一个公开作品，重试不会多发布一份；再次发布需要通过明确的更新操作更新快照，保留下载计数。公开快照不会随着私人修色自动改变。

用户可下架自己的公开作品，其他人不能下架；下架后无法继续浏览或新增下载。删除个人作品不自动删除公开快照或原图；若该作品已公开，删除确认明确告知仍需单独下架。

### 3.4 登录账号名称

作者名称来自账号资料，而不是每次发布的表单。

首次登录成功后，若账号尚无名称，用自定义「设置名称」面板完善一次，提供昵称输入与保存。用户可以暂时跳过，后端为该账号保存稳定的「豆友」加短随机标识，不使用 openid、用户 ID 或手机号作名称。之后在作品页的账号入口修改名称。

昵称输入采用微信支持的 `input type="nickname"`，普通文本输入作为兼容回退；由用户主动填写或选择，不依赖已收回的 `getUserProfile` 获取真实头像昵称。此流程不要求手机号或头像，不阻断游客浏览或本机旧作品查看。发布页始终不增加昵称字段。

账号名称限制为去除首尾空白后的 1–24 个 Unicode 字符，拒绝控制字符；不要求全站唯一，因为身份隔离仍基于服务端用户 ID。帖子展示和作者搜索读取当前账号名称，修改账号名称后过去发布作品的署名一起更新。

参考：[DCloud 昵称输入说明](https://uniapp.dcloud.net.cn/component/input)、[DCloud 微信用户信息接口调整说明](https://uniapp.dcloud.net.cn/api/plugins/login.html?id=getuserinfo)。

## 4. 固定顶栏与共享自定义弹层

### 4.1 布局

`app-header` 固定定位，结合 `windowInfo` 和微信胶囊测量状态栏与导航高度，输出等高占位，避免内容被顶栏盖住。不使用固定写死的 iPhone 刘海尺寸；窗口变化时更新测量。

首页搜索和筛选固定在导航下面；其他页面保持同一导航高度和边界。详情全屏层也使用相同安全区布局，不能再额外叠加两份顶部 padding。

底部工具栏只避让一次原生 tabBar 与安全区，不新增巨大空白。转图继续使用真正的 tab 页面；公开详情、发布和跟拼可以是有返回入口的独立页面。

### 4.2 组件职责

- `ui-host`：每个页面挂载一个共享宿主，管理本页业务遮罩、层级、反馈和关闭生命周期。
- `app-sheet`：登录、账号名称、作品操作、正面 / 镜像导出等底部面板的统一外壳。
- `app-dialog`：删除、下架及其他破坏性操作的简短确认。
- `app-toast`：已保存、发布成功、错误与重试等短提示；可见反馈不使用原生 toast。
- `app-loading`：登录、上传、发布、导出等忙碌状态；重复点击禁用，不用无法结束的 loading。
- `src/lib/ui.js`：保留现有调用入口，由页面宿主承接 Promise / 事件，不让各页面重复拼装弹窗。

页面离开后取消或清理本页未完成的弹层请求，不把上页确认结果送到新页。遮罩禁用底层查看器手势，关闭时保留画布位置和缩放。业务层不以原生弹层作为兜底。

微信 / iOS / Android 自己的相册权限、隐私授权、相册选择等系统界面无法替换；仅这些平台管理的授权与系统操作继续由平台提供。

## 5. 我的作品与自动保存

作品页只保留账号入口、全部 / 在拼 / 已完成筛选、新建入口和作品卡片。卡片展示图纸、短名称、格数 / 色数和跟拼进度，通过更多面板提供查看、导出、发布、删除等操作。

保存、修色与完成一行仍先可靠写入本机作品仓储，列表立即更新。已登录时后台自动推送，登录完成、作品页展示或网络恢复时拉取自己的作品；不再让用户点击「同步作品」。

同步协调器合并连续操作并串行处理，复用已有 revision / CAS / tombstone / 冲突副本语义，避免一个旧请求覆盖更新后的图纸。网络失败保留本机数据和待处理标记，有限退避重试；账号变化时沿用当前账号隔离，不静默转移作品。

「已保存」只表示本次作品已持久化，不能冒称后端也已成功。公共发布必须等后端保存完成才允许提交；后台暂时不可用时以短提示说明当前操作未完成，不显示虚假的发布成功，也不恢复同步状态卡片。

## 6. Node.js 接口与下载计数

复用现有 Express、mysql2、鉴权、限流及 `{ ok, data }` / `{ ok: false, error }` 响应格式；新增独立社区路由与仓储，不把公共数据塞进个人 `works.list`。

| 接口 | 规则 |
| --- | --- |
| `GET /api/profile` | 已登录；读取自己的账号名称 |
| `PATCH /api/profile` | 已登录；只更新自己的名称 |
| `GET /api/community` | 游客可用；关键词、最热 / 最新、游标、每页最多 20 项 |
| `GET /api/community/:id` | 游客可用；只返回仍公开的图纸及作者展示信息 |
| `GET /api/community/:id/thumbnail` | 游客可用；受控读取由公开图纸生成的 PNG，不读取原图 |
| `POST /api/community` | 已登录；读取本人源作品与指定版本，发布快照 |
| `PUT /api/community/:id` | 已登录且为作者；明确更新标题与公开快照 |
| `DELETE /api/community/:id` | 已登录且为作者；幂等下架 |
| `POST /api/community/:id/download-intents` | 游客可用；创建有过期时间的一次导出凭据 |
| `POST /api/community/:id/downloads` | 导出相册保存成功后上报，凭据去重，返回最新下载次数 |

搜索使用参数化 SQL，限制关键词长度并转义 LIKE 通配符。最热依次按下载次数、发布时间、ID 降序；最新按发布时间、ID 降序。客户端搜索和分页响应以当前关键词 / 排序作用域为准，旧响应不覆盖新列表。

### 下载次数定义

一次下载指用户发起公开图纸导出且前端收到相册保存成功。查看详情、打开导出面板、拒绝权限、取消、生成失败和开始拼均不计数。

导出开始前申请一个与公开作品绑定、约 10 分钟有效的服务端凭据；同一次导出的确认重试使用同一凭据。成功后在事务内标记该凭据已消费并将下载量原子加一，重复确认只返回同一结果，不二次加一。原作品已下架或凭据过期时不新增计数。

计数上报失败时保留短期重试任务，已经保存到相册的文件不重复保存。前端不能直接设置总下载量；下载意图和确认接口均限流。

相册保存是设备本地能力，后端不能独立证明真实系统回调。因此这是一项受限流和幂等保护的客户端成功上报统计，不是具备防刷证明的计费指标；本轮不承诺完全杜绝恶意刷量。

## 7. 数据与文件隔离

新增非破坏性迁移脚本，并同步初始化 schema。迁移只修改本项目数据库，不改 MySQL root 密码、不清空已有作品、不操作其他端口或数据库。

### 账号表扩展

为 `bead_users` 增加可空 `display_name`。原用户不强制马上补全资料；首次访问资料时按照上面的稳定默认名称规则补齐。登录响应返回账号展示名称，但鉴权仍只依赖服务端签发令牌。

### `bead_public_works`

字段包含服务端 UUID、作者用户 ID、私有源作品 ID、源 revision、公开标题、公开 pattern 快照、缩略图对象标识、下载次数、创建时间、发布时间、更新时间及下架标记。作者与源作品的组合唯一，支持重复发布幂等；热门和最新各有对应排序索引。

公开快照使用现有图纸格式和 MARD 白名单，不存原图 ID、个人进度或用户提交的任意颜色映射。关联私人作品只在后端使用，不暴露给游客。

### `bead_public_downloads`

字段包含随机意图 ID、公开作品 ID、确认凭据摘要、创建时间、过期时间和完成时间。意图 ID 唯一；确认与作品下载数更新在同一事务内，防止并发重试重复统计。定期清理已过期未完成意图；下载总数保留在作品表，不保存原始 IP、openid 或明文会话令牌作为排行榜数据。

### 公开缩略图

后端依据通过校验的公开图纸与固定 MARD 色卡生成缩略图，存入独立的社区衍生文件目录，通过受控路由提供。不能开放现有私有原图上传目录，不能接受客户端远程图片 URL。

生成、落盘和数据库保存失败不发布半成品。更新时先完成新缩略图和快照再切换引用，仅清理本次失败的临时衍生文件；下架不删除私人原图。

本轮仍是本地开发，不配置 OSS、不部署公网。正式公开运营前，内容审核、举报处理和发布合规配置作为独立上线准备事项，不将本地运行冒称为已可公开上线。

## 8. 动效与用户验收

新卡片从 `translateY(24px)`、轻微透明入场，在接近落位时到 `-4px`，最后回到 `0px`。单卡约 280ms，错峰约 45ms，最大延迟约 200ms。只动画 transform 与 opacity，布局高度提前确定；不从零比例缩放，不导致其他卡片抖动。

首次加载、切换搜索 / 排序后的新列表和触底新增批次播放一次；滚动、切回已缓存页面或更新下载数字不重复动画。减少动画模式下取消回弹并降低或关闭入场过渡；点按反馈保持短且克制。

以下仅是用户验收清单，不由代理执行：

1. 每个页面滚动时顶栏不移动，胶囊不被内容遮挡；转图底部不出现重复安全区空白。
2. 登录、错误、删除、下架、导出使用同一风格的自定义弹层；系统相册授权仍正常。
3. 首页没有灵感页签和旧营销区，瀑布流确实错列；关键词 / 作者搜索、排序和续页符合预期。
4. 发布页没有昵称输入；账号名称设置一次后自动用于发布，改账号名后历史署名同步改变。
5. 游客能浏览下载，不能发布、修改账号或修改 / 下架他人的作品；公开响应不包含原图和私有数据。
6. 详情、导出和材料图例显示真实 MARD 色号，不显示 HEX；正面 / 镜像图纸文字不反转。
7. 正常相册保存加一，取消 / 失败不加；确认重试和并发请求不重复加；重新刷新排序体现新热度。
8. 私人作品保存后自动出现在列表，已登录背景保存与进度同步可重启恢复；取消手动同步 UI 不丢数据。
9. 发布更新、下架和网络失败不生成重复帖子或半成品；私人原图保持私有。
10. 新卡片错峰上浮并轻回弹，已有卡片滚动不重复；图纸详情缩放不出现反复放大缩小。
