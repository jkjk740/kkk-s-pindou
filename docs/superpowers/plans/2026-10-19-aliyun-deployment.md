# 豆屿阿里云部署计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 将现有后端、完整数据库及用户图片迁移到已购买的杭州 ECS，使本机微信小程序连接云端，并留下可重复发布及回滚步骤。

**Architecture:** 沿用既有 Node.js/Express/MySQL 架构；服务器采用 Node 24 LTS、单进程 systemd、本机 MySQL 8 和 Nginx。源码按版本发布，环境文件和图片目录独立持久化。域名备案未完成时，优先使用受控的本地 SSH 转发进行模拟器开发，正式域名访问在备案完成后配置。

**Tech Stack:** Node.js 24 LTS、MySQL 8、Nginx、systemd、uni-app。

**Spec:** `docs/nodejs-local-and-aliyun.md`、当前用户要求部署、同步本地用户/作品/图片并记录发布步骤。

## Global Constraints

- 不创建分支或提交；不清库、不重置密码、不影响其他项目或服务。
- 仅迁移豆屿的 `bead_island` 数据库和配套图片；接收端如有既有业务，先备份并核对冲突，不能覆盖。
- 私钥和后端秘密不进入源码、前端或聊天；生产配置单独保存。
- `3001`、`3306` 仅本机监听；不为调试开放数据库或 Node 端口到公网。
- 保留正式小程序 HTTPS/合法域名限制；本机开发例外只针对当前开发输出。
- 不运行额外测试、lint、用户业务验收或收费 AI 请求。部署所需进程、数据库结构、文件校验及连接就绪检查单独记录。

## Review Focus

- 数据库与私有图片必须来自同一停止写入的快照，保留所有权、图片引用、图纸进度。
- 不能向已有远程业务库直接导入带 DROP 的全量转储，不能只凭表名存在就跳过结构核对。
- Nginx 代理后限流必须读取真实客户端 IP，且只信任 loopback 代理及覆写后的转发头。
- 发布切换不能覆盖持久图片、生产配置，失败时可切回旧版本。
- 证书签发不等于部署；域名备案、微信合法域名及续期状态须如实记录。
